partition

Splits the source into two observables, one with the values the predicate accepts and one with the rest; each subscribes the source itself.

Sample: the drawn spec as code, both halves merged and tagged

// at(ms, v): v at ms; end(ms): complete at ms; 1 frame = 1 ms
const at = (ms, v) => timer(ms).pipe(map(() => v));
const end = (ms) => timer(ms).pipe(ignoreElements());
const [odd, even] = partition(merge(at(2, 1), at(4, 2), at(8, 3), at(15, 4), at(18, 5), at(22, 6), end(25)), (x) => x % 2 === 1);
merge(odd.pipe(map((x) => 'odd ' + x)), even.pipe(map((x) => 'even ' + x)))

3 essential criteria

the predicate
x % 2 === 1: 1, 3, 5 go to the first half, 2, 4, 6 to the second
two subscriptions
each half is the source filtered, so subscribing both subscribes the source twice
the pair
is returned at once, at 0; the values follow in their own frames

Resulting sink

odd 1 at 2, even 2 at 4, odd 3 at 8, even 4 at 15, odd 5 at 18, even 6 at 22, complete at 25

Workflow

  1. The pair of observables exists from the subscription at 0; nothing has been emitted yet.
  2. 1 at 2 is odd and goes to the first half; 2 at 4 is even and goes to the second; and so on, every value landing in exactly one half.
  3. Both halves complete with the source at 25.

In the spec

The output lane has the two halves as marbles x and y at 0, and under it two rows, each a filtered copy of the source lane; the source lane carries two subscription bars, one per half.

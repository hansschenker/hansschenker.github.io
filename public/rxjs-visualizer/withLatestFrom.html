withLatestFrom

On every source value, emits it together with the latest value of the other input; source values before that are dropped.

Sample: the drawn spec as code, one frame per millisecond

// at(ms, v): v at ms; end(ms): complete at ms; 1 frame = 1 ms
const at = (ms, v) => timer(ms).pipe(map(() => v));
const end = (ms) => timer(ms).pipe(ignoreElements());
const e2 = merge(at(2, 1), at(5, 2), at(7, 3), at(9, 4), end(13));
merge(at(1, 'a'), at(4, 'b'), at(10, 'c'), at(12, 'd'), at(14, 'e'), end(16))
  .pipe(withLatestFrom(e2, (letter, n) => letter + n))

3 essential criteria

trigger
only e1 values produce output
e2
is only read; its 2, 3, 4 at 5, 7, 9 produce nothing by themselves
before its first value
source values are dropped: a at 1

Resulting sink

b1 at 4, c4 at 10, d4 at 12, e4 at 14, complete at 16

Workflow

  1. a at 1 finds no value from e2 yet and is dropped.
  2. b at 4 is paired with the latest of e2, 1: b1. e2 goes on to 2, 3, 4 without any output.
  3. c, d, e at 10, 12, 14 all read the latest, 4; the output completes at 16 with e1.

In the spec

Compare with combineLatestWith on the same inputs: here only e1 values drop onto the operator row, e2 values do not, and a at 1 has no marble on the output lane.

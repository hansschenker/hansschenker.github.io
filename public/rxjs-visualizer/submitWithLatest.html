submit with the latest form value

A form: each submit reads the latest form value, invalid ones are dropped, valid ones are saved.

Sample: the drawn spec as code, one frame per millisecond

// at(ms, v): v at ms; end(ms): complete at ms; 1 frame = 1 ms
const at = (ms, v) => timer(ms).pipe(map(() => v));
const end = (ms) => timer(ms).pipe(ignoreElements());
const form = merge(at(1, 'j'), at(3, 'jo'), at(7, 'joe'), at(12, 'joel'), end(20));
const save = (value) => merge(at(3, 'ok'), end(4));
merge(at(4, 's'), at(9, 's'), at(16, 's'), end(20))
  .pipe(
    withLatestFrom(form),
    map(([, value]) => value),
    filter(value => value.length >= 3),
    switchMap(save),
  )

3 essential criteria

withLatestFrom(form)
pairs each submit with the latest form value; form values on their own emit nothing
map and filter
keep only the form value, and only when it is at least 3 characters long
switchMap(save)
saves the value with a cold that answers ok after 3 frames

Resulting sink

ok at 12, ok at 19, complete at 20

Workflow

  1. The submit at 4 reads jo, the latest form value; too short, filter drops it.
  2. The submit at 9 reads joe and saves it: ok at 12.
  3. The submit at 16 reads joel and saves it: ok at 19; the form and the submits complete at 20.

In the spec

The form lane sits above the withLatestFrom row and every one of its values drops onto that row, but only the submits produce a pair on the lane below. The filter lane has a gap at 4, and the two saves hang from it.

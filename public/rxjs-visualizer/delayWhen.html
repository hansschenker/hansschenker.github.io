delayWhen

Delays each value until the observable its duration selector returns for it emits; every value gets a selector subscription of its own.

Sample: the drawn spec as code, the selector a 1-frame timer

// at(ms, v): v at ms; end(ms): complete at ms; 1 frame = 1 ms
const at = (ms, v) => timer(ms).pipe(map(() => v));
const end = (ms) => timer(ms).pipe(ignoreElements());
merge(at(2, 'a'), at(5, 'b'), end(8))
  .pipe(delayWhen(() => timer(1)))

3 essential criteria

the duration selector
returns the cold '-x--|' for every value: its x comes 1 frame after subscription
per value
the selector is subscribed when the value arrives and unsubscribed as soon as it emits
completion
the output completes with the source at 8, once no value is still waiting

Resulting sink

a at 3, b at 6, complete at 8

Workflow

  1. a at 2 subscribes the selector; it emits at 3 and a is emitted, the selector dropped.
  2. b at 5 does the same and comes out at 6.
  3. The source completes at 8 with nothing pending: the output completes.

In the spec

Two inner rows, one per value, each a one-frame subscription bar ending at the x of the selector; the values land on the output lane in the columns where those bars end.

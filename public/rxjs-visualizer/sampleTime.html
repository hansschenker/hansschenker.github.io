sampleTime

On its own clock, emits the latest value that arrived since the previous tick, if any.

Sample: the drawn spec as code, one frame per millisecond

// at(ms, v): v at ms; end(ms): complete at ms; 1 frame = 1 ms
const at = (ms, v) => timer(ms).pipe(map(() => v));
const end = (ms) => timer(ms).pipe(ignoreElements());
merge(
  at(0, 'a'), at(4, 'b'), at(6, 'c'), at(16, 'd'), at(19, 'e'),
  at(23, 'f'), at(25, 'g'), at(27, 'h'), end(30),
).pipe(sampleTime(7))

3 essential criteria

clock
ticks every 7 frames from subscription: 7, 14, 21, 28
a tick emits
the newest value since the previous tick, or nothing
on completion
nothing pending is flushed; the output just completes

Resulting sink

c at 7, e at 21, h at 28, complete at 30

Workflow

  1. the tick at 7 finds a, b and c since subscription and emits the newest, c.
  2. the tick at 14 finds nothing new and emits nothing; the tick at 21 emits e, which replaced d at 19.
  3. the tick at 28 emits h; the source completes at 30 and the output with it. The tick due at 35 never comes.

In the spec

The operator row shows the clock: a tick mark every 7 frames opening the next window; the window ending at 14 is empty, the others end where an arrow drops the sampled value.

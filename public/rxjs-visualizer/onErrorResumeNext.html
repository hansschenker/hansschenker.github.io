onErrorResumeNext

When the source errors or completes, continues with the next observable instead, swallowing the error; the output ends when the last one does.

Sample: the drawn spec as code, written with the creation function (source.pipe(onErrorResumeNext(e2)) is the same)

// at(ms, v): v at ms; end(ms): complete at ms; 1 frame = 1 ms
const at = (ms, v) => timer(ms).pipe(map(() => v));
const end = (ms) => timer(ms).pipe(ignoreElements());
const fail = (ms) => timer(ms).pipe(map(() => { throw new Error('boom'); }));
const e2 = merge(at(2, 'c'), at(5, 'd'), end(8));
onErrorResumeNext(merge(at(2, 'a'), at(5, 'b'), fail(8)), e2)

3 essential criteria

the error
at 8 on the source: not passed on, the source is unsubscribed and e2 subscribed in the same frame
e2
a cold, so its marbles count from 8: c at 10, d at 13, completion at 16
the ending
the output completes with e2; a source completion would hand over the same way

Resulting sink

a at 2, b at 5, c at 10, d at 13, complete at 16

Workflow

  1. a and b pass through at 2 and 5.
  2. The source errors at 8: nothing reaches the output, e2 is subscribed at 8.
  3. c and d at 10 and 13 come from e2, which completes at 16, and the output with it.

In the spec

The red cross on e1 at 8 has no counterpart on the output lane; the e2 lane’s marbles and subscription bar start in that column, like catchError’s replacement, and its two values drop onto the operator row.

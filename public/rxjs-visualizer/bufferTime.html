bufferTime

Collects values into arrays and emits one array per interval of its own clock.

Sample: the drawn spec as code, one frame per millisecond

// at(ms, v): v at ms; end(ms): complete at ms; 1 frame = 1 ms
const at = (ms, v) => timer(ms).pipe(map(() => v));
const end = (ms) => timer(ms).pipe(ignoreElements());
merge(
  at(3, 'a'), at(7, 'b'), at(11, 'c'), at(15, 'd'), at(19, 'e'),
  at(23, 'f'), at(27, 'g'), end(33),
).pipe(bufferTime(10))

3 essential criteria

clock
closes a buffer every 10 frames from subscription and opens the next
a buffer
is emitted when it closes, even when empty
on completion
the open buffer is emitted before the output completes, here the empty one at 33

Resulting sink

[a, b] at 10, [c, d, e] at 20, [f, g] at 30, [] at 33, complete at 33

Workflow

  1. at 10 the first buffer closes holding a and b.
  2. at 20 the second closes with c, d and e; at 30 the third with f and g.
  3. the source completes at 33 while the fourth buffer is open and empty: [] is emitted, then the output completes.

In the spec

The operator row shows the clock windows of 10 frames, each ending where a pill with the buffer drops onto the output lane; the last window is cut at 33, where the empty pill shares the frame with the completion, (z|).
